# Working in this app

## Keep files focused

- Keep onboarding code within `src/features/onboarding` and generic controls in `src/components`.
- Components should describe the interface. Extract stateful workflows into feature-local hooks when that makes them reusable or easier to understand.
- Extract non-React transaction and validation work into focused functions rather than hiding it in a large hook.
- Aim for roughly 200 lines or fewer per handwritten production file. Treat size as a prompt to review responsibilities, not a reason to fragment related code mechanically.
- Reuse existing hooks and shadcn components before introducing another abstraction. Keep dependency flow one-way and use type-only imports for types.
- Perps and Spot completion reuse SetupActions, with the existing Perps Share/Workspace actions passed as content/props. Spot offers Pending requests without login instead of the wallet Workspace action, without adding local Spot saves to the wallet catalog. Spot Create new uses the shared create-new confirmation and resets only Spot to App name; cancel returns focus and preserves saved details. Keep busy guards and 44px targets.
- Reuse the same `StartOverButton` in Creator/API and Spot footers; keep its 44px height, equal horizontal padding and keyboard focus behavior together rather than styling each caller independently.
- Use mostly Tailwind utilities for component appearance, layout, responsive behavior, and states. Reuse shared control variants; reserve custom CSS for theme tokens, global defaults in the base layer, and motion that needs global handling.
- Preserve public module exports when moving implementation details so callers do not need unrelated edits.
